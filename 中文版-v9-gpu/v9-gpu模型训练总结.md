# 中文 GPT 模型训练总结 v9

- 日期：2026-09-05 ~ 2026-09-06
- 硬件：RTX 4060 Laptop（8GB 显存）
- 代码：`gpt_zh_v9-gpu.py`
- 定位：**v8 基础上唯一改动 = 步数 20000 → 32000（E 2.46 → 3.94）**，验证「延长训练」在干净配方下的边际收益，并探测数据量天花板

有趣的巧合：v9 在第 20000 步的 val = 3.6063，与 v8 终点 3.6061 几乎重合——余弦拉长导致的中段劣势（此时 v9 LR 仍有 1.1e-4）在末端被完全追回，随后 12000 步净赚 0.145。

### 2.4 关键结论

1. **预登记目标超额达成**：预测 best val 3.50~3.55，实际 **3.4611**，多赚约 0.04
2. **数据天花板信号完整出现**：29200 步创最优后，**连续 7 次评估（29600~31999，共 2800 步）val 再未创新低**，稳定在 3.49~3.52；同时 train 仍在下行（3.28 → 3.23）——模型还在背训练集，但泛化已停滞。E=3.94 基本就是这份 0.66 亿 token 训练集对 234M 模型的喂养极限
3. **best checkpoint 机制再次证明价值**：最终模型 val 3.5185，最优模型 3.4611，差 0.057——用 final 做推理等于白丢一半本轮收益
4. v9 的最优出现在 91% 进度处（29200/32000），晚于 v8 的 92%（18400/20000），规律一致：余弦收尾段出最优

## 三、优化建议

### 3.1 v10 已获充分授权：加数据

v8 总结里写的触发条件——「24000 步后 train 还在降但 val 连续 3 次评估不创新低」——本轮完整命中（连续 7 次）。**v10 = 语料 0.1b → 0.2b（已清洗），其余全部沿用 v9**：

| 项目 | v10 预期 |
|---|---|
| T_train | ≈ 2亿字符 × 0.739 ≈ **1.48亿 token**（训练集约 1.33亿） |
| E | 2.62亿 / 1.33亿 ≈ **1.97**（退回甜点区腹地，过拟合间隙应收窄） |
| 耗时 | ≈ 18.4 小时（同 32000 步） |
| 预测 best val | **3.35~3.45**（数据翻倍 + 长训练双杠杆） |

两个必须执行的配套动作：

1. **val 集变更预警**：0.2b 语料重新切分后 val 与 v8/v9 不再相同，v10 的 val 数字与前作**不可直接对比**。训练完成后必须用 v9 的验证集对 `model_best_zh_v10.pt` 补测一次（v9 代码检查时已给脚本），那个数才能和 3.4611 比
2. **RAM 预警**：ids 列表翻倍至 ~5GB，16GB 内存机器建议改用 numpy int32 拼接（v9 代码检查时给的 3 行改法）

### 3.2 欠账：生成质量验收

v8 起就欠着。**用 `model_best_zh_v9.pt`（val 3.4611）做 temperature 0.8 / top-k 50 采样**，与 v6（3.83）盲测对比——loss 累计降了 0.37，连贯性提升应该肉眼可辨。代码现成：`load_mode_generate_txt_streaming()` 已指向 best checkpoint。

### 3.3 不建议做

- **E > 4**（如 40000 步）：本轮已证实 0.1b 数据在 E≈3.9 到顶，再延长只会拉大过拟合间隙
- **继续扩模型**：D/20N = 0.063，数据翻倍前扩参数没有意义
