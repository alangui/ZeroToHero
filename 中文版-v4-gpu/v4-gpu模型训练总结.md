# 中文字符级 GPT 模型训练总结（v4：性能调优 + 模型扩容至 9610 万参数）

> 训练时间：2026-08-29 ｜ 硬件：RTX 4060 Laptop（8G 显存, CUDA）｜ 框架：PyTorch
> 前序实验见：《中文GPT模型训练总结.md》（v1）、《中文GPT模型训练总结_v2.md》（v2）、《中文GPT模型训练总结_v3.md》（v3）

## 一、训练配置与数据集

### 1.1 模型结构（本轮核心变化：容量 ×3）

| 参数 | v3（对照） | **v4（本轮）** |
|---|---|---|
| 参数量 | 32,613,305（约 3260 万） | **96,133,049（约 9610 万）** |
| n_layer / n_embd / n_head | 8 / 512 / 8 | **12 / 768 / 12**（GPT-2 Small 尺寸，head_size=64） |
| block_size | 256 | 256 |
| dropout | 0.2 | 0.2 |
| 分词方式 | 字符级 | 字符级 |

### 1.2 训练超参数

| 参数 | 值 |
|---|---|
| batch_size | 64 |
| max_iters | 10000 |
| 学习率策略 | warmup 100 步 + 余弦衰减（3e-4 → 3e-5） |
| 优化器 | AdamW（weight_decay=0.1） |
| 精度 | **AMP FP16 + GradScaler**（v3 为 FP32） |
| 注意力实现 | **F.scaled_dot_product_attention（Flash Attention, is_causal=True）** |
| 显存优化 | **梯度检查点（gradient checkpointing）** |
| 评估策略 | 每 200 步评估一次，每次 20×2 个批次 |

### 1.3 数据集（与 v3 相同）

| 项 | 值 |
|---|---|
| 总字符数 | 18,655,205 |
| 训练集 | 16,789,684 |
| 验证集 | 1,865,521 |
| 训练 token 总量 | 10000 × 64 × 256 ≈ **1.64 亿 tokens（约 9.8 epoch）** |

### 1.4 本轮解决的性能问题（附记）

本轮训练前曾出现异常：58M 参数的模型单步耗时高达 21~23 秒。排查定位为 **显存溢出**——batch 64 无检查点时峰值显存 10.7GB，超出 8GB 后 Windows WDDM 将数据溢出到共享显存（内存条），每步在 PCIe 上来回搬运。启用梯度检查点后峰值降至 2.4GB，速度恢复正常。本轮即便模型扩容到 96M 参数，显存峰值也仅 **4138 MiB（约占 8GB 的一半）**。

### 2.2 训练开销

- 总耗时：**261.0 分钟（约 4.35 小时）**
- 纯训练速度：约 150 秒 / 100 步 = **1.5 秒/步**（全程稳定在 149.7~150.6 秒，无降速）
- 吞吐：约 **1.09 万 tokens/秒**
- 每次 loss 评估（20×2 次前向）：约 13 秒，全程 51 次评估共约 11 分钟
- 显存：峰值 4138 MiB，reserved 5194 MiB，全程 0 次 OOM
- 模型扩容近 3 倍，总耗时反而比 v3（449.7 分钟）缩短 **42%**——AMP + Flash Attention + 梯度检查点的组合收益

### 2.3 与历史实验对比

| 实验 | 硬件 | 数据量 | 参数量 | 最终 train / val loss |
|---|---|---|---|---|
| v1（dropout 0.2, 固定 lr） | Mac M1 | 408 万 | 3150 万 | 3.3626 / 4.1092 |
| v2（dropout 0.3, 余弦衰减） | Mac M1 | 408 万 | 3150 万 | 3.8037 / 4.1354 |
| v3（余弦衰减 + 扩数据） | RTX 4060 | 1866 万 | 3260 万 | 3.5779 / 3.3768 |
| **v4（性能调优 + 扩容）** | **RTX 4060** | **1866 万** | **9610 万** | **3.1234 / 3.1274** |

### 2.4 结论

1. **扩容收益完整兑现**：同数据集下参数 ×3，val loss 3.3768 → **3.1274**（-0.25），train loss 同步降 0.45，符合缩放定律（scaling law）预期；
2. **零过拟合**：终态 train 3.1234 ≈ val 3.1274，差距仅 0.004。全程 val 略低于 train 是 dropout 在训练时开启 + 按位置切分导致验证集文本偏简单所致，属正常现象；
3. **数据与模型达到新平衡**：v1 时代 train/val 裂口 0.75 的过拟合已彻底消失，但这也意味着 1866 万字符的数据量开始限制 96M 参数模型的进一步发挥；
4. **末段收益递减**：最后 1000 步 val 仅降 0.016，学习率已触底，本配置下再加步数性价比不高；
5. **工程突破**：通过「AMP + Flash Attention + 梯度检查点」三板斧，8GB 显卡驯服了 96M 参数模型，且吞吐比 v3 提升约 4 倍。

## 三、优化建议

### 3.1 当前模型：作为新的基线封存

val 3.13 取代 v3 的 3.38 成为新基线。此配置的算力/数据/模型三者已均衡，不建议在同配置下追加训练。

### 3.2 下一步优先级（按性价比排序）

1. **再次扩充语料（最优先）**：1866 万 → 5000 万~1 亿字符。train ≈ val 说明模型还有容量富余，数据是当前最短的那块板；
2. **换 BPE 分词（质变级改造）**：用 sentencepiece 训练 8000~16000 的词表。字符级把大量容量浪费在"学组词"上，BPE 后相同 block_size 能装下约 2 倍的语义内容，是中文场景性价比最高的架构升级（注意：BPE 的 loss 数值与字符级不可直接比较）；
3. **继续放大模型**：检查点 + AMP 下峰值显存才 4.1GB，还有近一半余量，可尝试 n_layer=16 / n_embd=1024，或把 batch_size 提到 96~128 提升 GPU 利用率；
4. **加长上下文**：block_size 256 → 512，让模型学会段落级的连贯结构（配合梯度检查点显存可控）。

### 3.3 锦上添花项

- **权重共享（weight tying）**：`lm_head.weight = token_embd.weight`，省 300 万+参数且通常小幅提质；
- **生成采样调优**：推理时加 temperature（0.8~1.0）和 top-k（50~200）采样，生成文本的多样性和可读性会明显好于纯多项式采样；
- **评估集改进**：当前按位置切分（前 90% 训练 / 后 10% 验证），前后文本难度不均会造成 val 系统性偏低；可改为随机抽样切分，让 val loss 更能反映真实泛化能力。
