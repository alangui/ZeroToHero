### 2.4 结论

1. **扩数据收益完整兑现**：val loss 4.11 → 3.38，远超调参手段的总和，验证"数据瓶颈"诊断；
2. **曲线形态健康**：train/val 全程贴合、同步下降、无过拟合裂口（val 持续略低于 train，系按位置切分导致验证集文本偏简单）；
3. **边际收益递减**：末段每 500 步仅降约 0.01，学习率触底，单纯加步数已不划算；
4. 生成质量：词句连贯、段落有叙事感，达到本架构（字符级 + 3000 万参数）的合理上限。

## 三、优化建议

### 3.1 当前模型：封存为基线

val 3.38 作为字符级中文 GPT 的 v1.0 基线保留，不建议再投入步数。

### 3.2 下一步杠杆（按优先级）

1. **BPE 分词（sentencepiece, ~8k 词表）**：同窗口上下文覆盖文字量翻倍，生成质量方向性提升（loss 口径改变，以生成效果为裁判）；
2. **加大模型**：数据 epoch 数仅 8.8，容量仍有空间，可试 n_layer=10、n_embd=640（参数约 6000 万），预期 val → 3.1~3.2；
3. **训练加速**：4060 的 Tensor Core 尚未启用——开启 AMP（`torch.autocast` + `GradScaler`）+ TF32，单步可从 2.6s 降至 1s 内；`torch.compile` 在 Windows 中文系统有编码兼容问题，需设 `PYTHONUTF8=1`；
4. **工程改进**：定期保存 checkpoint（每 2000 步），防止 7 小时长跑中断归零。

### 3.3 硬件笔记

- RTX 4060 Laptop 与 M1 Pro/Max 在 FP32 小模型训练上性能接近（带宽瓶颈型负载）；4060 的优势在 FP16/TF32 Tensor Core，需显式开启才能兑现；
- 8G 显存对本模型宽裕，加大 batch 到 128 可进一步提高吞吐。
