# 中文 GPT 模型训练总结 v10（终版 · 含基准集翻案）

- 日期：2026-09-07 ~ 2026-09-08
- 硬件：RTX 4060 Laptop（8GB 显存）
- 代码：`gpt_zh_v10-gpu.py`
- 定位：**v9 基础上唯一改动 = 语料 0.1b → 0.3b（训练 token 0.66亿 → 2.0亿，E 3.94 → 1.31）**

### 2.4 关键结论

1. **数据扩量杠杆有效，v10 实至名归**：E 从 3.94 降到 1.31 后，v9 探明的数据天花板被数据本身搬走——同模型同步数，净赚 **-0.236**，是 v 系列单变量实验史上第二大收益（仅次于 v6→v8 的模型扩容 -0.274）
2. **v10 自家 val 3.1784 ≈ 基准 3.1819**——v10 的验证集读数一直是诚实的，没有被泄漏抬高
3. **v9 vs v8 在基准上仅差 0.063**：延长训练到 E=3.94 的收益比自家 val 显示的（0.14）缩水一半，印证「E 接近 4 时已在硬挤重复数据」
4. 梯队总跨度：v6 → v10 累计 **-0.573**（每字符 2.78 → 2.36），模型扩容与数据扩量各贡献约一半

### 2.5 误诊复盘（教训存档）

初版总结曾判定 v10「真实收益仅 -0.014」，依据是「v10 在 v9 验证集补测 = 3.4473」。基准集建立后真相大白：

- 该补测脚本硬编码加载 `model_best_zh_v9.pt`，3.4473 与 v9 自家 val（3.4611）在噪声内一致——**实际误测了 v9 自己**，v10 从未被跨集评过
- 由此构建的「0.3b 泄漏污染」结论对 v10 是冤案；语料取证发现的 0.3b ⊇ 0.1b（100% 包含）属实，但它污染的是**旧 val 集的读数**（如 v9 在 v10 val 上沾光 0.05），不是 v10 的模型质量
- **教训两条**：① 评估脚本必须把被测模型路径打在输出里、且杜绝硬编码默认值；② 任何「负面结果」在宣判前，先核对测量对象是不是本人

## 三、优化建议

### 3.1 已固化的新规范（本轮产出）

1. **永久基准集是唯一成绩口径**：`benchmark_val.pt`（9944 万 token）冻结，所有版本只报基准集数字；自家 val 仅用于训练中监控趋势
2. **评估脚本三要素**：被测模型路径打印在输出首行、结构配置用探针从 checkpoint 反读（`n_layer/n_embd/n_head` 不再靠记忆）、无硬编码默认值
3. **语料扩充先体检**：重复率 + 与既有语料的包含关系，写进数据准备流程（0.3b 内部重复率 4.39%，v11 起用去重版 `wiki_corpus_0.3b_dedup.txt`）

### 3.2 v11 方向（按优先级）

| 方向 | 理由 | 预测 |
| --- | --- | --- |
| **模型扩容**（如 n_layer 16→24，~340M） | 数据侧 2.0亿 token 已就位，D/20N=0.056 仍远小于 1，扩模型恰逢其时；v6→v8 已验证此杠杆单次收益 -0.27 量级 | 基准 **≤3.10** |
| 架构现代化（RoPE/RMSNorm/SwiGLU 三选一） | 同参数白赚 0.05~0.15 | 基准 -0.05~-0.15 |
| 继续加数据到 0.4b | 边际已薄（v10 的 E=1.31 尚未到顶，加数据不如加模型） | 暂缓 |

单次只动一个变量，纪律不变。

### 3.3 欠账提醒

- **生成质量验收**（v8 欠到现在）：用基准最强的 `model_best_zh_v10.pt` 做 temperature 0.8 / top-k 50 采样，与 v6 盲测对比——基准差 0.57，肉眼可辨才对
