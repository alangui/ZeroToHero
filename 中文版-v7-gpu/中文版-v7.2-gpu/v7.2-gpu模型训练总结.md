## 三、判读：tying 定罪，clip 无罪释放

**v7.2 的轨迹与 v7 几乎逐点重合**（400 步 7.49 vs 7.38，2800 步 6.40 vs 6.39，5000 步 6.06 vs 6.05）——单独加回权重共享，就完整复现了 v7 的病态。证据链闭合：

```
v7   = 扩层 + batch减半 + tying + init + clip  → 病态（≈6.05 @5000）
v7.1 = 扩层 + batch减半                        → 健康（4.27 @5000）
v7.2 = 扩层 + batch减半 + tying(+init)          → 病态（6.06 @5000）← 复现！
```

**结论：v7 倒退的元凶是权重共享（及其配套初始化）；梯度裁剪、扩层、batch 减半全部无罪。**

### 为什么 tying 在你这套 recipe 里毒性这么大？

GPT-2/nanoGPT 用 tying 没问题，但你的配置有三个叠加因素：

1. **梯度双重身份冲突**：embedding 要表示语义，输出头要拉开词间区分度，两路梯度在同一参数上互相牵制，收敛被拖慢；
2. **与 weight decay 的恶性交互**：AdamW wd=0.1 持续收缩共享权重 → 输出 logits 尺度被压制 → softmax 区分度上不去；独立 lm_head 本来可以自由长大来对冲，tying 把这个自由度没收了；
3. **0.02 小初始化放大前两者**：输出端从一开始就被压在低尺度，在 5000 步的短程训练里迟迟爬不出来。

教训：**任何"经典技巧"都有隐含的适用条件**（GPT-2 的 tying 搭配的是全套 0.02 初始化体系、6e-4 lr、50 万 token 的 batch），脱离上下文搬运技巧需要实验验证——这正是消融实验的价值。

## 四、最终结论与正式版 recipe

**v8 正式长跑 = v7.1 配置**（2.35 亿参数、无 tying、无 clip、batch 32、20000 步）：

- 梯度裁剪：v7.1 全程无 clip 训练稳定，正式版可不加；若想保险，用宽松版 `clip=5.0`（只拦尖峰，不碰常态）；
- `save_best_model_flag` 记得改回 `True`；
- 预计 10~10.5 小时，预期最优 val **跌破 v6 的 3.83，目标 3.5~3.6 区间**。
