> 训练时间：2026-09-03 17:55 ~ 2026-09-04 04:58（11.05 小时）｜ 硬件：RTX 4060 Laptop（8G 显存, CUDA）
> 前序实验见：《中文GPT模型训练总结.md》及 v2~v6 各版
> **实验意图：v6 基础上模型 ×2（12层/768维 → 16层/1024维），同语料同 token 总量，验证扩容收益**

## 三、结果分析：一次明确的「负结果」

**模型翻倍、数据相同、算力相同，val 反而恶化 0.87——且 train loss 同步变差，说明问题不在泛化（裂口健康），而在优化本身：同样的 token 流，v7 学得更慢。**

本轮同时引入了 5 个变量（扩层、权重共享、新初始化、梯度裁剪、batch 减半），违反了「一次只改一个变量」的实验纪律，导致无法直接归因。按嫌疑度排序的假设：

1. **梯度裁剪可能过紧（嫌疑最大）**：若训练中梯度范数常态化大于 1.0，每步 clip 等于在余弦 schedule 之上再偷偷打一个折扣，等效学习率被拉低，全程「学不动」——曲线形态（斜率持续偏缓但无异常波动）与此吻合；
2. **权重共享的双重身份约束**：输出层被迫与输入 embedding 共用 0.02 小初始化，早期 logits 被压制，可能拖慢收敛；
3. **weight decay 剂量翻倍**：步数 ×2 而 wd=0.1 不变，累积权重衰减约为 v6 的 2 倍，过度收缩权重；
4. **16 层深度缺乏残差初始化缩放**：GPT-2 官方对残差路径投影层使用 std=0.02/√(2·n_layer) 的缩放初始化，本轮未做，深层残差方差累积可能增加优化难度；
5. **batch 减半的梯度噪声**：噪声 ×√2，lr 未相应下调，warmup 100 步对 16 层模型偏短。

## 四、下一步：消融实验计划（每个 1~2 小时可验证）

用 3000~5000 步的短跑逐个剥离变量，全部与 v6 同时点对比：

| 实验 | 配置 | 验证假设 |
|---|---|---|
| A | v7 配置 + 打印裁剪前梯度范数 | 若常态 ≫1，假设 1 坐实，改为 clip=5.0 或取消 |
| B | v7 配置 − 权重共享 | 隔离假设 2 |
| C | v7 配置 + wd=0.05 | 隔离假设 3 |
| D | v6 完整配置用新代码重跑（含随机切分） | 排除「代码改动/切分方式」引入的隐藏 bug |

关键改进：**在训练日志里加一行梯度范数记录**（`clip_grad_norm_` 的返回值就是裁剪前范数，顺手 log 即可），让优化状态从此可见：

```python
scaler.unscale_(opt)
grad_norm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
if iter % 100 == 0:
    logging.info(f"梯度范数(裁剪前): {grad_norm:.2f}")
```

## 五、结论与教训

1. **v6（val 3.83）依然是当前最优模型，v7 不回滚代码但回滚结论**——推理/生成请用 v6 的 `model_best`；
2. 负结果的价值：它精确指出了「2 亿参数 + 现有 recipe」在这个数据规模下不 work，并给出了 5 个可证伪的假设；
3. 最重要的方法论教训（也是本轮唯一真正犯的错）：**一次引入 5 个变量**——工程改动（内存/速度）和算法改动（tying/clip/init）应该分批上线。下轮恢复单变量纪律；
4. 每字符换算勘误：v6 总结中按小说语料汇率（0.664）估算的 2.54 偏低，wiki 语料汇率约 0.739（1 token ≈ 1.35 字符），v6 修正为 ≈**2.83/字符**，v7 为 ≈3.47/字符；跨语料对比需以 token 级 loss 为准。
