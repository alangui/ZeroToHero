# 中文 GPT 模型训练总结（v7.1：消融实验 —— v7 倒退归因，病灶锁定）

> 训练时间：2026-09-04 12:53 ~ 15:23（2.5 小时）｜ 硬件：RTX 4060 Laptop（8G 显存, CUDA）
> 实验性质：**v7 负结果的消融实验**。v7 同时引入 5 个变量导致 val 倒退 0.87，本实验剥离其中 3 个
> **与 v7 的唯一差别：移除权重共享、移除 std=0.02 初始化、移除梯度裁剪（保留 16层/1024维 + batch 32）**

## 一、实验配置

| 参数 | 值 |
|---|---|
| n_layer / n_embd / n_head | 16 / 1024 / 16（与 v7 相同） |
| 参数量 | **234,538,624**（输出层独立，比 v7 多 1638 万 ✓ 验证改动生效） |
| 权重共享 / 新初始化 / 梯度裁剪 | **全部移除**（输出层回到 Linear 默认初始化） |
| batch_size / max_iters | 32 / **5000**（短跑消融，D = 0.41 亿 token） |
| 数据 | wiki 语料 7386 万 token，与 v6/v7 完全相同 |
| 其余 | 余弦 lr 3e-4→3e-5（5000 步版）、dropout 0.2、AMP、Flash Attention、梯度检查点，不变 |

## 三、判读：按预设决策规则，病根锁定

同 D = 0.41 亿 token 的三方对照：

| 实验 | 配置 | 同 D 的 val loss |
|---|---|---|
| v6 @ 2500 步 | 1.1 亿参数（健康参照） | 4.4786 |
| v7 @ 5000 步 | 2.18 亿 + tying + init + clip（带病） | ≈6.05 |
| **v7.1 @ 5000 步** | 2.35 亿，三变量移除 | **4.2681** ✅ |

**结论（按 v7 总结中预设的判读规则）：**

1. **v7.1 落在 4.0~4.5 区间 → 16 层/1024 维的模型本身没有问题**，"v7 的倒退 = 权重共享 / 初始化 / 梯度裁剪三者之一（或组合）所致"，假设坐实；
2. **大模型的优势首次显现**：扣除 schedule 衰减完成的 0.1~0.2 便宜后，v7.1（4.27）仍优于 v6 同时点（4.48）——同样的数据流，2.35 亿参数比 1.1 亿学得快；
3. train/val 裂口仅 0.09，无过拟合，曲线末端仍在下降——模型还没吃饱。

### 4.2 正式长跑（推荐直接做）

归因实验属于学术兴趣，工程上可以直接用 v7.1 的干净 recipe 长跑：

- `max_iters = 20000`（D = 1.64 亿，E = 2.5 epoch，与 v6/v7 对齐）
- **`save_best_model_flag` 改回 True**
- 预计耗时 ≈ 10~10.5 小时（1.81 s/步 × 20000 + 评估）
- 预期最优 val **< 3.83**（v6 基线），有希望落在 3.5~3.6 区间——v7.1 在同 D 下已领先 v6 约 0.2，且大模型后劲更足

## 附：实验谱系

```
v6 (1.1亿参数, 干净recipe)          val 3.83 @ D=1.64亿   ← 当前最优基线
v7 (2.2亿, +tying+init+clip)       val 4.70 @ D=1.64亿   ← 多变量翻车
v7.1 (2.35亿, 移除三者)             val 4.27 @ D=0.41亿   ← 病灶锁定在移除的三者中
     └─ 同D对比: v7≈6.05 / v6=4.48 / v7.1=4.27
```

**方法论注脚**：v7 一次引入 5 个变量导致不可归因；v7.1 一次移除 3 个变量完成「分组定位」——接下来若想知道具体是哪一个，用 v7.2/v7.3 逐个加回即可。这就是消融实验的标准打法：先二分，再细分。
