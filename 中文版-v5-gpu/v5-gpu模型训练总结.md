# 中文字符级 GPT 模型训练总结（v5：BPE 分词改造对照实验）

> 训练时间：2026-09-01 20:02 ~ 2026-09-02 00:45 ｜ 硬件：RTX 4060 Laptop（8G 显存, CUDA）｜ 框架：PyTorch + sentencepiece
> 前序实验见：《中文GPT模型训练总结.md》（v1）、《_v2.md》（v2）、《_v3.md》（v3）、《_v4.md》（v4）
> **实验设计：与 v4 唯一的变量是分词方式（字符级 → BPE），语料、模型结构、超参全部保持一致**

## 一、训练配置与数据集

### 1.1 分词器（本轮核心变化）

| 项 | v4（字符级） | **v5（BPE）** |
|---|---|---|
| 工具 | `set(text)` 自建字表 | **sentencepiece BPE** |
| 词表大小 | 7095（全是单字+标点） | **16000**（4 特殊符号 + 256 字节兜底 + 15740 学到的词条） |
| 换行处理 | `\n` 天然在词表中 | `user_defined_symbols=['[BR]']`，行间插入 |
| 压缩率 | 1 字符 = 1 token | **1.51 字符 = 1 token**（1865 万字符 → 1239 万 token） |

### 1.2 模型结构（与 v4 相同）

| 参数 | 值 |
|---|---|
| n_layer / n_embd / n_head | 12 / 768 / 12 |
| block_size / dropout | 256 / 0.2 |
| 参数量 | **109,816,960（约 1.098 亿）**——比 v4 多 1370 万，全部来自 embedding/输出头（词表 7095→16000，(16000-7095)×1537 ≈ 1368 万 ✓） |

### 1.3 训练超参数（与 v4 相同）

batch_size=64，max_iters=10000，warmup 100 步 + 余弦衰减（3e-4→3e-5），AdamW（wd=0.1），AMP FP16 + Flash Attention + 梯度检查点。评估间隔改为 500 步。

### 1.4 数据集（与 v4 同一语料，token 化后变小）

| 项 | v4（字符） | **v5（BPE token）** |
|---|---|---|
| 总量 | 18,655,205 | **12,392,605** |
| 训练集 | 16,789,684 | 11,153,344 |
| 验证集 | 1,865,521 | 1,239,261 |
| 训练 token 总量 | 1.64 亿 | 1.64 亿（相同步数） |
| **epoch 数** | 9.8 | **≈14.7（被动增加 50%）** ⚠️ |

## 二、训练效果

### 2.1 Loss 变化记录

| 步数 | train loss | val loss | 备注 |
|---|---|---|---|
| 0 | 9.8436 | 9.8442 | ≈ ln(16000)=9.68，正常起步 |
| 1000 | 6.2640 | 6.4455 | |
| 2000 | 5.5534 | 5.7688 | |
| 4000 | 4.9417 | 5.3277 | val 开始走平 |
| 6000 | 4.5688 | 5.2371 | |
| 8000 | 4.3042 | 5.1628 | val 几乎不动 |
| **9000** | 4.2571 | **5.1287（最优）** | val 触底 |
| 9500 | 4.2256 | 5.1410 | val 回升 |
| **9999** | **4.2004** | 5.1436 | **train/val 裂口 0.94** |

### 2.2 训练开销

- 总耗时：**283.6 分钟**（v4 为 261 分钟）；纯训练约 166 秒/100 步 = **1.66 秒/步**（v4 为 1.50 秒）
- 变慢原因：输出层/embedding 从 7095 维词表涨到 16000 维，logits 计算与 softmax 开销变大
- 显存峰值 4710 MiB（v4 为 4138 MiB），仍在 8GB 安全线内

### 2.3 与 v4 的公平对比（关键：换算成「每字符 loss」）

BPE 与字符级的 loss 不可直接比较，须换算：**每字符 loss = val loss ×（token 数 ÷ 字符数）**，压缩比 = 1,239,261 / 1,865,521 = 0.664。

| 实验 | 表面 val loss | 每字符 val loss | 过拟合裂口 |
|---|---|---|---|
| v4（字符级） | 3.1274 | **3.1274** | ≈0（健康） |
| **v5（BPE，最优@9000步）** | 5.1287 | **3.4070** | **0.94（四轮最严重）** |

**结论：本轮 BPE 改造在公平指标上反而退步了 9%。**

### 2.4 结果分析

1. **过拟合是主因**：token 压缩 1.51 倍 → 同样 10000 步，epoch 从 9.8 被动涨到 14.7。曲线呈现教科书式过拟合——train 一路降到 4.20，val 在 4000 步后走平、9000 步触底反弹。这不是 BPE 的失败，而是「数据量不变时，高效分词 = 更多 epoch = 更强记忆」的必然结果；
2. **曲线形态反转**：字符级时代 val 长期低于 train（dropout + 位置切分红利），本轮 val 从 500 步起就持续高于 train 且差距单调扩大——记忆效应压过了前两个因素；
3. **BPE 的理论收益被掩盖**：同样 block_size=256，BPE 能装下 1.5 倍的语义内容，这个优势要在「数据充足、不过拟合」的前提下才能兑现；
4. **对照实验的价值**：正是因为 v5 只改了分词这一个变量，才能干净地定位出——**当前阶段数据量是压倒一切的瓶颈**，任何架构/分词层面的优化都绕不开它。

## 三、优化建议

### 3.1 下一步（v6）：BPE + 扩语料，两个变量一起放

已备好的 4000 万字符语料现在可以上了：

- 4000 万字符 → 约 2650 万 token，10000 步对应 **~6.2 epoch**，回到健康区间；
- 注意用**新语料重新训练分词器**（词表分布要匹配新语料），再编码训练；
- 预期：v6 的每字符 val loss 应显著低于 v4 的 3.13，这才是 BPE 真正的验收场。

### 3.2 如果短期不扩语料，BPE 版本的救场措施

- **早停**：取 9000 步（val 最优 5.1287）的 checkpoint 作为本轮产物，后面 1000 步是负收益；
- **减步数**：按 9.8 epoch 对齐 v4，max_iters 设为 ~6700；
- **加正则**：dropout 0.2 → 0.3（v2 验证过能收窄裂口）。

### 3.3 流程固化建议

- **保存最优 checkpoint**：训练中跟踪 best val，只在 val 创新低时存盘（`save_best_only`），避免最终模型 = 最过拟合模型；
- **对比指标统一用「每字符 loss」**：今后任何涉及分词器改动的实验，都换算后再进对比表；
- **生成质量人工抽检**：过拟合模型的典型症状是大段背诵训练原文，生成时如果发现成段复述语料内容，即为记忆而非泛化。
